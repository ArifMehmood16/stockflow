## Deliver

Implement the approved run/tenant/warehouse schema using versioned, checksummed migrations. Keep public catalog/bootstrap tables compatible. Add a Java fixture command that derives real product IDs, creates bounded run-owned stock, persists ownership/seed/row-count receipts and skips verified repeats. ## First evidence or failing behavior

Before reservation work begins, provision the approved least-privilege fixture roles and separate read/write connection settings from A01. Record required setup-role privileges; missing role-creation authority is a blocker, not a reason to run the service as an unrestricted owner. Keep the diagnostic reader's connection read-only. Do not grant fixture writers access to unrelated schemas.

Migration twice preserves data; interrupted fixture creation cannot publish READY; mismatched migration checksum fails; cleanup of an unowned schema/database is rejected; an unrelated sentinel table survives.

Expose only completed fixtures. Actual fixture rows equal the selected limit bounded by available products; no duplicate expansion. Preserve prior runs, global catalog and existing quantities. Record disk/connection budgets and safely resume/rollback preparation.
