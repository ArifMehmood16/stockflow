PLAN mapping: 5.2. Status lives only in [STATE](../STATE.md).

## Read only what this task needs

## Deliver

Route eligible eventual reads to a replica, all writes and freshness-critical reads to the current primary. Implement scoped read-your-writes tokens, verified minimum version/replay evidence, bounded wait or primary fallback. If ownership/promotion changes, invalidate unsafe assumptions explicitly.

## First evidence or failing behavior

Lagged replica cannot satisfy a higher minimum version; wrong-run/tenant/item token fails; writes never route to replica. Timeout yields an explicit error/fallback outcome rather than a false fresh success.

## Acceptance criteria

UI/trace identifies source, observed version and lag basis. A bytes/LSN distance is not mislabeled as seconds. Replica read capacity does not increase primary write capacity.

## Verification

make test-replication-integration; token/security tests; controlled paused-replay scenarios; simulation and routing E2E. Use the exact current target names; add a target only where this card introduces it. Record the command and observed result. Never count unavailable infrastructure as a pass.

## Handoff evidence

Known-write read timeline and measured source/lag outcomes.

## Keep out of scope

No blanket replica reads, guessed replication delay or primary-capacity multiplication.
