## Deliver

Implement explicit detect → verify fencing → inspect possible loss → authorize promotion → promote → change route → verify known writes → reseed former primary. Persist transition/ownership evidence so controller restart cannot create two writers. Treat unknown fencing as a blocked operation. Require explicit acknowledgement for possible asynchronous loss.

## First evidence or failing behavior

Promotion without positive fencing is rejected; former primary never auto-rejoins writable. Controller restart at each transition recovers safely. Replayed requests use durable idempotency, with acknowledged missing writes reported honestly after async loss.

## Acceptance criteria

Measure RTO from a documented failure point to successful verified service and RPO against known committed writes; disclose unknown outcomes. Real failure injection targets only the owned cluster.

## Handoff evidence
