# G03 — Pause, copy and verify moving buckets

PLAN mapping: 6.3. Status lives only in [STATE](../STATE.md).
Prerequisite: G02.

## Read only what this task needs

Read the common workflow in [CURSOR](../../../CURSOR.md), then relevant sections of: G01/G02; approved transaction boundaries; durable migration metadata. Inspect existing collaborators/tests before edits. Paths for future features are proposed locations, not claims that files already exist.

## Deliver

Implement resumable pre-cutover migration for selected buckets: pause writes including reserve/release/expiry, drain in-flight work, copy stock plus reservations/idempotency and required metadata, then compare counts/checksums and business invariants. Old owner remains authoritative. Use bounded batches and explicit progress with interruption/cancel state.

## First evidence or failing behavior

Concurrent writes cannot slip past pause/drain; expiry worker obeys the same fence. Destination interruption/cancellation leaves old data authoritative. Duplicate copy does not duplicate rows. Verified count alone cannot hide a changed quantity/version.

## Acceptance criteria

Migration captures the correct mutable row closure. Retries/status during pause follow the contract, not a false success. Unmoved tenants remain active.

## Verification

make test-sharding-integration; deterministic pause/drain races, interrupted/resumed copy, checksum mismatch and cancellation tests. Use the exact current target names; add a target only where this card introduces it. Record the command and observed result. Never count unavailable infrastructure as a pass.

## Handoff evidence

Before/copy/verified ledgers including reservation and idempotency history.

## Keep out of scope

No ownership change before verification or pretending background copy alone is online rebalancing.

**Stop after this task and its commit. Wait for the owner to request another item. Do not start the next card automatically.**
