# I03 — Publish an honest portfolio evidence package

PLAN mapping: 8.2, 8.4 preparation. Status lives only in [STATE](../STATE.md).
Prerequisite: I02.

## Read only what this task needs

Read the common workflow in [CURSOR](../../../CURSOR.md), then relevant sections of: docs/evaluation.md; verified stage packets; dataset attribution; THIRD_PARTY_NOTICES.md. Inspect existing collaborators/tests before edits. Paths for future features are proposed locations, not claims that files already exist.

## Deliver

Produce a ten-minute guided demo script, architecture tour, screenshots, concise engineering case study and reproducible benchmark recipes/raw summaries. Separate modeled throughput from measured rates and record environment, exact workload, warm-up/repetitions, percentiles, drops and known failures. Verify dataset/product attribution and dependency notices; resolve project licence with owner.

## First evidence or failing behavior

Documentation recipes reproduce the stated scenario; empty/missing measurements cannot become zero or fabricated gains. Secret scan and export inspection contain no credentials/tokens or full catalog dump.

## Acceptance criteria

Claims are supported by committed sanitized evidence. Reviewers can explain each bottleneck/solution/trade-off and recover from a failed experiment.

## Verification

Docs/link checks; bounded benchmark repeats; dependency/image/secret scans; evidence recipe walkthrough. Use the exact current target names; add a target only where this card introduces it. Record the command and observed result. Never count unavailable infrastructure as a pass.

## Handoff evidence

Case study, raw summaries, screenshots and unresolved release/legal/hosting decisions.

## Keep out of scope

No invented latency/RTO/RPO, unlicensed asset copying or unapproved public deployment.

**Stop after this task and its commit. Wait for the owner to request another item. Do not start the next card automatically.**
