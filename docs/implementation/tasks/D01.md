# D01 — Build a bounded real load generator

PLAN mapping: 3.1. Status lives only in [STATE](../STATE.md).
Prerequisite: C04 and accepted V3.

## Read only what this task needs

Read the common workflow in [CURSOR](../../../CURSOR.md), then relevant sections of: Java controller runtime; approved inventory API and credentials; docs/operations.md proposed budgets. Inspect existing collaborators/tests before edits. Paths for future features are proposed locations, not claims that files already exist.

## Deliver

Implement fixed-target open-loop scheduling against registered inventory endpoints. Separate offered, started, scheduler-dropped, completed, failed and in-flight counts. Bound duration, rate, concurrency and queues; propagate deadlines. Generate valid tenant-scoped read/reserve/release operations and deterministic missing-key/hot-key distributions; include actual fixture/workload identity.

## First evidence or failing behavior

A slow target does not silently reduce offered arrivals; excess scheduled work is counted as dropped; emergency stop cancels dispatch promptly and bounded drain classifies outstanding work. Arbitrary URL/redirect targets are rejected.

## Acceptance criteria

Native hardware limits are reported separately from server bottlenecks. Browser disconnect/lease expiry stops unsafe unattended load. Never send modeled 250k req/s directly at the user's database.

## Verification

Introduce make test-load; fake-clock scheduler tests; tiny real HTTP integration with owned fixtures and hard ceilings. Use the exact current target names; add a target only where this card introduces it. Record the command and observed result. Never count unavailable infrastructure as a pass.

## Handoff evidence

Conservation ledger, scheduler lag/drop evidence and stop deadline.

## Keep out of scope

No unbounded virtual threads, paid/external target traffic or unapproved host stress test.
