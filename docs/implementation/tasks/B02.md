## Deliver

Build a Java discrete-event engine ordered by virtual time plus monotonic event sequence, with seeded randomness, finite service workers/pools, bounded queues, deadlines and read/write service times. Make queue/service distributions versioned inputs. Represent a million logical records compactly, without allocating one event/object per stored row or creating 250k browser particles.

## First evidence or failing behavior

Same seed/config/version yields the same event history; ties order consistently; queue overflow produces explicit drops; offered/started/completed/failed/in-flight balances hold. Pause freezes virtual time.

## Acceptance criteria

Simulation work has an engine budget and yields publication fairly. High modeled arrival rates stay distinct from real generator limits. No wall-clock sleeps or browser capacity formula controls engine results.

## Verification

Introduce make test-simulation; run deterministic replay, conservation, saturation and bounded-memory tests plus controller tests. Use the exact current target names; add a target only where this card introduces it. Record the command and observed result. Never count unavailable infrastructure as a pass.

## Handoff evidence

Small reproducible trace and measured engine memory envelope; no real PostgreSQL performance claims.

## Keep out of scope

No synchronous per-request UI events at huge rates or porting the old arithmetic multipliers as authoritative simulation.
